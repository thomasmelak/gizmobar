Getting started

This takes about five minutes.

Install

You need macOS 14 or newer. Pick whichever way you like; every option installs the same app.

  1. Download Gizmobar.dmg from the latest release.

  2. Open the DMG and drag Gizmobar onto the Applications folder.

  3. Open Gizmobar from Applications. The first time, macOS will block it because the app isn't notarized; see Opening it the first time below.

  4. The first launch links gizmo into ~/.local/bin. Copy the example config into ~/.config/gizmobar (it never overwrites):

    $ ~/.local/bin/gizmo config init

  1. Add the tap and install the cask:

    $ brew tap thomasmelak/gizmobar https://github.com/thomasmelak/gizmobar
$ brew install --cask gizmobar

  2. Homebrew clears the quarantine flag, puts gizmo on your PATH and starts the bar, so there's no security prompt.

  3. Copy the example config, and update later with brew upgrade:

    $ gizmo config init
$ brew upgrade --cask --greedy gizmobar

  1. Paste this into Terminal:

    $ curl -fsSL https://raw.githubusercontent.com/thomasmelak/gizmobar/main/install.sh | bash

  2. The script downloads the latest release into /Applications, clears the quarantine flag, links gizmo into ~/.local/bin, copies the example config and starts the bar. Nothing is built on your Mac and you don't need Xcode.

  1. Only needed if you want to work on Gizmobar itself. You need the Xcode Command Line Tools with Swift 6 (xcode-select --install).

  2. Clone, build and install:

    $ git clone https://github.com/thomasmelak/gizmobar.git
$ cd gizmobar
$ make install   # Gizmobar.app into /Applications, gizmo into ~/.local/bin
$ make config    # copy the example config
$ open -a Gizmobar

Opening it the first time. Release builds are signed in CI but not notarized by Apple, so the first launch of a downloaded copy shows a "cannot be opened" or "Apple could not verify" message. Open System Settings › Privacy & Security, scroll to the message about Gizmobar and click Open Anyway, or remove the quarantine flag in Terminal:

$ xattr -dr com.apple.quarantine /Applications/Gizmobar.app

Homebrew and the one-line installer do this for you.

Check that it's running with gizmo ping (→ pong). To start at login, set launch_at_login = true in config.toml, or start it from AeroSpace (see below).

Uninstall

Either of these removes the app, the gizmo command and the bar's state. Your config in ~/.config/gizmobar is kept.

$ brew uninstall --cask --zap gizmobar
$ curl -fsSL https://raw.githubusercontent.com/thomasmelak/gizmobar/main/uninstall.sh | bash

Or run make uninstall in a clone of the repository.

Coming from SketchyBar? Stop it first so the two bars don't overlap: brew services stop sketchybar, and remove its lines from aerospace.toml.

Configure

Everything lives in ~/.config/gizmobar/. Every key is optional; gizmo reload applies changes.

config.toml          # layout, bar, clock, icons, media, plugins
themes/<name>.toml   # your themes; missing keys fall back to Gizmo
icon-packs/<id>/     # extra or replacement icon packs
plugins/<id>/        # TypeScript plugins

A small config.toml:

theme = "gizmo"

[bar]
position = "bottom"          # bottom | top
height = 40
glass = true                 # glass pills on a transparent bar
autohide = "fullscreen"      # never | fullscreen | always

[layout]
left = ["logo", "workspaces"]
center = ["front_app"]
right = ["now_playing", "network", "system", "battery", "volume", "clock"]

[clock]
format = "EEE dd MMM HH:mm"

[[clock.world]]
zone = "America/New_York"
inline = true

Built-in widgets: logo, workspaces, front_app, now_playing, network, system, battery, brightness, volume, theme, clock, globe. Any plugin id goes in a layout list too. The full example with every option is examples/gizmobar/config.toml.

AeroSpace

With AeroSpace 0.21 or newer the bar keeps one aerospace subscribe stream open, so aerospace.toml needs no bar callbacks. To start the bar with AeroSpace:

after-startup-command = ['exec-and-forget open -g -a Gizmobar']

With more than one display, each bar shows only the workspaces AeroSpace has on that monitor, with the one it is showing highlighted. Set [aerospace] per_monitor = false to list every workspace on every bar.

Match the bar height with a gap, e.g. outer.bottom = 40 for a bottom bar. On older AeroSpace versions set [aerospace] mode = "callback" and add:

exec-on-workspace-change = ['gizmo', 'trigger', 'aerospace.workspace']

Now playing

Spotify and Music work out of the box; macOS asks once to let Gizmobar control them. For browsers, podcasts and any other app, install mediaremote-adapter and point the bar at it:

[media]
adapter = "~/.local/share/mediaremote-adapter"
spectrum = true    # live bars from a Core Audio tap (asks for audio capture once)

Without the adapter the bar falls back to nowplaying-cli when it is installed. Deny audio capture or set spectrum = false and the bars animate on their own.

Themes and icons

Twelve themes are bundled: Gizmo, Nord, Dracula, Catppuccin Mocha, Tokyo Night, Gruvbox, Rosé Pine, Kanagawa, Everforest, One Dark, Solarized and Default. Pick one from the theme widget, or set theme = "nord". Your own themes/<name>.toml wins by name.

App icons resolve per bundle ID: a per-app override, then your custom pack, then the other packs in order, then the fallback. Start your own pack and drop <bundle-id>.svg files into it; the bar picks them up live:

gizmo icons init my-icons      # then set [icons] custom_pack = "my-icons"
gizmo icons missing            # apps without an icon, most used first

Right-click any app icon on the bar to switch it to the system icon or choose a file.

Your first plugin

brew install esbuild           # the bar rebuilds plugins on every save
gizmo new my-plugin            # ~/.config/gizmobar/plugins/my-plugin

Add "my-plugin" to a [layout] list and edit index.ts:

import { definePlugin, ui, fmt } from "@gizmobar/sdk";

export default definePlugin({
  id: "my-plugin",
  setup(ctx) {
    const cpu = ctx.use("cpu", { every: "2s" });
    return () => ui.row({ icon: "cpu", label: fmt.percent(cpu.value?.usage ?? 0) });
  },
});

List what it uses in plugin.json ("permissions": ["provider:cpu"]) and save. Types for every provider are in the generated gizmobar.d.ts. The plugin guide covers widgets, popovers, fetch, storage, 3D scenes and the guard rails. Four examples ship in examples/gizmobar/plugins.

CLI

CommandWhat it does
gizmo pingCheck that the bar is running
gizmo reloadRe-read config, theme and icon packs
gizmo statePrint what the bar currently shows
gizmo trigger <topic> k=vPush your own event onto the bus (plugins get it with ctx.on)
gizmo icons missingApps the icon packs don't cover, most used first
gizmo icons init <id>Start a custom icon pack
gizmo new <id>Scaffold a TypeScript plugin
gizmo config initCopy the example config into ~/.config/gizmobar (never overwrites)
gizmo typesPrint the @gizmobar/sdk declarations
gizmo debugPlugin render times, budget overruns and provider update counts
gizmo plugins reload|log|resume <id>Reload a plugin, show its console, resume a paused one

Troubleshooting

The bar doesn't show up

Run gizmo ping. If it can't connect, the app isn't running: open -a Gizmobar. If a config error stops it, check Console.app for "Gizmobar".

Privacy prompts come back after every build

The app is signed ad hoc. Install with SIGN_IDENTITY set (see Install, step 2).

Now playing is empty for a browser

Install mediaremote-adapter and set [media] adapter. Spotify and Music need the automation prompt accepted: System Settings → Privacy & Security → Automation → Gizmobar.

A plugin shows a warning pill

Hover it for the error, or run gizmo plugins log <id>. A plugin that keeps blowing its 2 ms render budget is paused; gizmo debug shows it and gizmo plugins resume <id> brings it back.

make test can't find Testing

Use make test, not swift test. With only the Command Line Tools, the Makefile adds the swift-testing framework path that SwiftPM misses.
